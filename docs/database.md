# 数据库设计

SQLite包含30个业务实体，完整类型、默认值和外键以 `prisma/schema.prisma` 为准。迁移位于 `prisma/migrations`。下表根据当前schema列出实际持久化字段；String金融字段保存规范化十进制，JSON内容（规则、标签、评分、标注等）保存为字符串，服务层验证其结构。DateTime统一UTC。

## 关系和业务不变量

- Platform → Account → AssetBalance。平台名称唯一，账户在平台内名称唯一，资产code全局唯一，持仓按账户+资产唯一。同资产跨账户按同一个assetId合并，账户归档保留持仓和历史。
- AssetTransaction关联账户、资产，可关联Transfer；TradeFill唯一关联一条流水。同账户流水sequence唯一，同交易成交sequence唯一。迁移以原rowid在同时间戳内回填顺序，保证已有数据重放。
- Transfer关联来源/目标账户及资产；源端、在途、到账三种状态只计算一次全局资产。余额重建依据quantity、costDelta、realizedDelta和cashDelta。
- Strategy → StrategyVersion → TradingPlan/Trade/BacktestSession。版本号在策略内唯一，发布后服务拒绝改写。Trade → TradeFill/PositionEvent/TradeReview/TradeAttachment。
- TradeAttachment可归属真实交易或策略版本；图片base64及MIME存储在数据库内，state只传元信息。复盘scores包含数值及当时评分规则快照。
- BacktestSession → Candle/BacktestTrade。K线按任务+时间唯一；模拟交易带branch及入场/出场index，回退保留旧branch。无真实账户或流水外键。
- AccountCashFlow每条来源流水唯一。全局收益只取EXTERNAL，账户收益包括内部流；AccountValuation按账户+时间唯一。PortfolioSnapshot按币种+时间唯一，关联类别配置快照。
- FinancialGoal名称唯一；ImportBatch内容hash唯一，关联逐行结果ImportRow；externalId在全局账本唯一保证跨批重复检测。SystemSetting以key为主键。AuditLog记录关键操作。SyncJob当前仅预留。

## 存储、备份与迁移

默认数据库为 `data/tradeos.db`。演示demo.db、单测unit.db、浏览器e2e.db分别隔离。数据库、原生WAL/SHM、恢复前备份和附件不能提交Git。

使用 `npm run db:setup` 生成客户端、结构元数据并执行已提交迁移。schema修改应生成新迁移，不使用推送schema覆盖财务数据。schema-metadata.json是备份字段/结构指纹来源，必须随schema一起生成。

恢复按外键依赖顺序插入、逆序清空，同一事务内校验结构、引用、余额重放、成交汇总及模拟盈亏。恢复前JSON保存于数据库旁的backups目录（默认data/backups），权限0600，不受运行工作目录改变影响。校验和检测损坏，但不是加密或签名。跨结构版本的备份需明确迁移，不能直接忽略指纹。
