# 深入使用验收与修复

2026-10-10，用户确认继续深入验收。该轮保持原产品范围，使用独立测试和验收数据库。

| 问题                                                              | 修复结果                                                                             | 验证                                                             |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 合约成交、转账可使用未来时间，归档账户仍可新增计划/合约成交       | 共用记账入口校验时间及账户状态；开仓和持仓事件拒绝未来/倒序，成交不能早于上一事件    | 数据库回归验证拒绝时交易、余额和状态不变                         |
| 普通卖出、转账可能消耗未平仓现货，导致后来无法平仓                | 余额更新检查全部未平仓交易占用；正常减仓先释放对应数量；恢复时也核对占用             | 自由数量可卖出，占用部分拒绝，最终能正常平仓；不一致旧备份拒绝   |
| CSV导出的负调整变成带单引号文本，非法金额在格式预览阶段抛解析异常 | 普通负十进制保留数值，公式文本转义；金额校验稳定返回格式问题，空白可选字段使用默认值 | 负数CSV从下载到映射、预览和导入，100−20.01=79.99                 |
| 在途价格有效期固定为7天，与用户设置不同                           | 持仓、在途和合约统一使用设置值                                                       | 30天/1天切换回归                                                 |
| 快照忽略指定时间，后更新负债可能进入过去的快照                    | 新增历史快照表单，按指定时点重建资产和负债审计记录，未来时间拒绝                     | 历史快照与UTC时间核对；负债100→50时历史仍为100                   |
| 历史对账用当前转账/合约状态，可能遗漏过去的风险状态               | 按对账时点查询在途及合约持仓；不完整时不给差额                                       | 后来已到账的转账在过去时点仍识别为在途                           |
| 现货可误用合约乘数                                                | 现货创建统一为乘数1                                                                  | 品种参数回归                                                     |
| 金额没有可用的精确排序                                            | 持仓金额列启用排序，用Decimal比较负值、小数及大额                                    | 单元测试精度边界；浏览器0.12/0.9正反排序                         |
| standalone切换工作目录后备份落入构建目录                          | 按数据库绝对路径定位backups，保存在持久数据目录                                      | 旧产物复现失败，新产物独立运行测试核对JSON内容、权限及SQLite文件 |
| 网络错误暴露技术异常、计划保存后旧预览残留                        | 共用表单保留失败输入、提供连接恢复提示，成功后清除预览                               | 非法金额纠正后保存；模拟网络失败时保留输入                       |

最初新增7个复现测试全部失败；修复后全量48项单元/数据库/访问保护测试通过，11条E2E通过。类型、代码规范、生产构建和本地运行结果见testing.md；独立运行验证还覆盖静态资源、JSON恢复和SQLite备份。新增测试留在项目内，可重复运行。

手工浏览器验证了创建平台/账户/现金资产、非法金额保留、纠正后保存，以及历史快照。新增表单检查桌面和手机；没有对原设计做无关美化。截图证据在本机`.impeccable/review/hardening-history-*.png`，不包含真实个人账本。

没有修改数据库结构，完整JSON备份结构版本保持兼容；恢复新增一致性校验会拒绝现货持仓已被其他流水消耗的不一致备份。缺少负债初始历史时不虚构历史金额。已有快照作为已保存历史保留，不自动改写；需要更新时应使用新的有效时点记录。

仍未验证Docker容器运行和大规模压力场景，开发工具链依赖告警保留原报告边界。未来行情同步和自动交易不在本轮范围。
