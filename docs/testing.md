## 财务和一致性重点

- 超大额及极小量Decimal往返；现货加权成本、部分退出、费用净额；资金不足事务回滚。
- 在途转账、到账重复拒绝、费用只计一次；同资产跨账户、币种估值、负债和可投资房地产配置。
- 已发布策略不可修改；独立成交与唯一账本关联；合约保证金占用、线性/反向风险及盈亏。
- 盈亏因子、期望、平均R、回撤、TWR和XIRR；账户资金流隔离；缺少边界时拒绝TWR；亏损交易仍可高评分。
- 历史余额与合约状态重建、汇率单独归因、同一时间成交顺序；现金利息和CSV重录不会重复扣费。
- 非法OHLC拒绝、未来K线隔离、双触发保守规则、回退分支；真实账本不受模拟影响。
- 零收益和通胀FIRE、退休缺口；完整备份、结构和校验和拒绝、坏外键及财务关联恢复回滚、账本重建一致。
- loopback Host允许、恶意Host、恶意/null Origin拒绝。

## 性能样本与部署边界

在演示账本（22条流水、5个账户、8项资产、约283天报价）测得开发服务首次请求含编译：state约450ms、analytics约1252ms、FIRE约364ms。数据是单次观察，不能当作生产延迟或大数据承诺。生产构建已成功；没有万笔流水及多年分钟K线压力测试。

Docker CLI可用、Compose配置可解析，但当前机器的Docker守护进程未运行，socket不可用，容器镜像和原生模块在容器内的运行仍待有环境时验证。本地开发与生产启动验收不依赖Docker。

## 已知边界

完整audit的5项high集中在braces/micromatch/fast-glob及Next ESLint开发工具链。本次生产依赖audit为0；未通过破坏兼容性的强制升级消除开发工具告警。后续依赖升级应复跑上述检查。

金融模型只覆盖文档明确的现货、线性、反向合同；XIRR是有界扫描求根，不证明数学上的全域唯一；收益率缺少记录时返回不可计算；未分解的估值变化保留归因残差。FIRE固定收益模拟不提供收益保证。CSV只重建普通独立流水，完整系统恢复必须用JSON。

本次没有实时价格同步、交易所实盘连接或多用户远程部署验收，这些不属于首版范围。

本轮使用独立acceptance.db做手工浏览器操作，unit.db和e2e.db做回归，不向正式账本写入测试记录。新增7项复现测试在修复前全部失败，修复后加入更多边界测试，总数由34增至48；E2E由7增至11。

修复覆盖未来金融记录、归档账户、未平仓现货占用、负数CSV及错误格式校验、在途估值有效期、历史快照和负债、历史对账、现货乘数、金额排序及网络错误提示。详情见acceptance-followup.md。
